## How a row reads

`- [x]` is closed within the linked evidence only; `- [ ]` is open. **ID — status — layer**: the condition. *Evidence*: the E-ids in [CAPABILITY_MATRIX.md](CAPABILITY_MATRIX.md) that bear on the row, followed by the row's qualification note. **Remaining:** what is still unproven. **Next:** the concrete next action. Statuses: `validated_bounded` (closed for the named model/package/platform/workload only), `partial` (some bounded evidence, condition not met), `active` (being worked), `planned` (not started), `missing` (no evidence yet).

## Rules

Stable ids are preserved. A row closes only with named model/runtime/package/device evidence, request and output identity, failure and cleanup results, and its remaining exclusions stated. Failed results are retained; a later pass never rewrites an earlier fail. A new binary, a new source commit or a different device inherits nothing. ENGINE_CONTRACT covers coherent intended-modality output, actual encoding/storage, controls, protocol, routing and lifecycle. MODEL_QUALITY retains factual, semantic and cosmetic outcomes. HUMAN_PRESENTATION covers media and human review. A coherent wrong answer or cosmetic image miss alone does not fail the engine; broken requested schema enforcement, controls or lifecycle still does.

Dated ledger changes (the 2026-09-22 reconciliation and every later continuation) are indexed in [history/README.md](history/README.md).
