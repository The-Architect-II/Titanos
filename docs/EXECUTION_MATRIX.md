## Execution modes per model (model x slot pairs with mode receipts)

Each column is one mode run by the matrix kit on that slot: single, two replicas, model sharding over a homogeneous GPU group, tensor parallel over that group. `na` means Titanos refused the mode for that model by design (recorded from its refusal text, or by construction from its own admission rules in src/titanos/config.py, or shared from the single/replicas refusal of the same pair), or the slot can neither form the GPU group the mode needs nor declare the explicit CPU/XPU group through a runtime available for the row backend, by construction; `untried` means no receipt for that mode on a slot where Titanos admits it and the slot can form or declare the group (a GPU slot without a group in the run, or the explicit CPU/XPU tensor-parallel group the kit does not run).

Matrix-kit admission and resource qualification (tools/matrix_kit/run_cells.py, containment.py, ingest.py). The kit admits a cell only when three consecutive samples clear its floors. The default floor is the artifact floor (max(global floor, 1.5 x artifact bytes x copies + margin) of host commit; artifact bytes x copies + margin of GPU memory) and no manifest field lowers it. The only lower host floor is *contained admission*: the row's spec names placement `resident` explicitly (`auto` may fall back to CPU offload and is never admitted under a lowered floor), the slot has a GPU, and the host can cap the owned process tree with a Windows Job Object; the Titanos server is then created suspended inside a kill-on-close job, the job commit cap is set and read back before the child resumes (a readback mismatch, or the OS refusing the job while the child is suspended, leaves the cell untried `containment_unavailable`, never an uncontained run), a shared-host reserve (--host-reserve-gib, positive, validated at the CLI with --floor-margin-gib) stays free, and the cap is 1.5 x a measured within-bound peak + margin (a profile entry is used only when it is bound to an existing pass receipt with verdict within and the same key, peak and cap; the receipt records the provenance) or, on a first run, what the host can spare minus the reserve. The bound is commit-only (`resource_qualification.bound` = `job_commit`): JOB_OBJECT_LIMIT_JOB_MEMORY caps and measures the tree's commit charge, and it is a fail-closed bound only for the allocation classes containment.CAP_SEMANTICS lists as enforced (measured 2026-09-25 with synthetic children: heap/VirtualAlloc commit, CUDA device allocations under WDDM, pinned host memory, safetensors safe_open, and FILE_MAP_COPY / mmap ACCESS_COPY views, each refused at the cap); two gaps remain: copy-on-write mappings made by torch.UntypedStorage.from_file(shared=False) are accounted in PeakJobMemoryUsed but not refused at map time and fail at page touch (the same exit code run r3 showed while a DiT shard loaded, 0xC0000005; which class r3 hit is not proven), and anonymous pagefile-backed sections are neither accounted nor refused. PeakJobMemoryUsed also includes attempted charges that were refused, so a peak over the cap is evidence of an attempted charge, not proof of committed memory over the cap. Every contained receipt carries that table as `resource_qualification.cap_semantics`; the guard remains the active monitor, available physical memory is sampled beside commit at admission and by the guard (a contained cell trips when it drops under the reserve), the tree's peak working set is recorded uncapped, and the owned child must avoid the gap classes (the adapter's streamed loader). Before a contained cell launches, a WDDM-aware pre-launch check reads the GPU driver model (nvidia-smi driver_model.current, recorded as `driver_model`) and sizes the entry's safetensors headers at the resident dtype (numel x itemsize; peak set = max(planner, dit) + text encoder + vae for the music bundle): on WDDM, where device allocations are charged to the process commit, the cap must be at least 3 GiB base (torch import + CUDA context) + peak set + 4 GiB activation headroom, else the cell is untried `blocked_by_host_resources: contained budget below the device-resident need on WDDM (cap X < base + peak set + headroom Y)` with the numbers in `device_resident_estimate` and nothing launched; on TCC the estimate is recorded only; an unreadable driver model or unreadable headers fail closed. Admission fails closed: a missing required commit, physical-memory (contained) or GPU reading is never treated as clear, three missing readings leave the cell untried (resource_reading_unavailable), STOP is checked once more immediately before success and once more immediately before the launch (a STOP there creates no process). While the cell runs, a guard samples host commit, physical memory, GPU memory and the job peak at least every 2 s during server start, model load, every active request and the unload (the request catalogue polls it in its wait loops); STOP, a missing reading, a cap hit, host commit or physical memory below the reserve, or (contained cells only) GPU memory below half the margin trips it, only owned work is cancelled (the Titanos job through DELETE /api/jobs, then the owned tree), and the partial receipt is kept as untried with its samples and cleanup evidence, including host commit, physical and GPU readings after the tree ended. Every receipt separates `exercise` (output correctness) from `resource_qualification` (kind, bound, verdict within/exceeded/unknown/not_contained, cap, measured peaks, samples, cleanup): a cell is a pass only when the exercise passed and the verdict is within or not_contained; exceeded or unknown makes it untried even when a valid output (a WAV) was written, and a cap hit is never a pass plus a note. Every receipt carries `receipt_schema` 2 with that complete block (not a summary) and RUN_RESULT carries `kit_schema` 2. ingest.py reads a current run (kit_schema >= 2) through its detailed receipts alone: a pass/fail cell whose receipt is missing, unparseable, without receipt_schema >= 2 or without the block is untried (receipt_missing_or_unparseable / receipt_schema_missing; no fallback to the RUN_RESULT row, whose resource_* fields are display only), and a contained_resident block is accepted only when its typed validation finds nothing wrong: verdict within under bound job_commit, positive integer cap and reserve, integer floors, the cap readback equal to the cap with JOB_MEMORY | KILL_ON_JOB_CLOSE set and breakaway clear, child in job, verified before resume, a measured job peak strictly under the cap, limit_hit false, readings_complete true, no trip, a non-empty sample sequence with non-decreasing timestamps covering model_load and request in which host commit and physical memory never dipped under the reserve and the job peak never exceeded the cap, a complete placement identity (profile_key, receipt_sha256 and adapter_sha256 as 64-character lowercase sha256 hex, placement resident, dtype, integer copies >= 1), cleanup evidence (launched, active_processes_after 0, job handle closed, a final query without error) and an exercise block equal to the row state; an artifact_floor block must say not_contained. Any problem makes the cell untried resource_qualification_evidence_incomplete with the functional output retained separately in the note; exceeded and unknown stay untried as before. Old full-artifact receipts are preserved only through the explicit legacy boundary: a RUN_RESULT without kit_schema is legacy when its utc is before 2026-09-25T19:00:00+00:00 (ingest.LEGACY_RESULT_BOUNDARY_UTC) and is then bound exactly as before (the family records kit schema 1); one without the marker at/after the boundary is refused unless --legacy-run names it. A verifier's upheld flag counts only when it is exactly boolean true (ingest and the builder alike).

## Reading this matrix

A pass is one named model on one named slot with a receipt; it is not a claim about other models, other devices of the same family or other workloads. Untried cells are the build-toward list: runnable by construction and not yet executed (the artifact present or still to be acquired; the note names the runtime tokens that grant the path), runnable by construction on a slot no fleet host covers yet (a host circumstance, never a construction fact), or executed by a reader without matrix-cited evidence. Not-applicable cells are refusals Titanos recorded by design or impossibilities by construction, not product decisions: the row backend has no execution path on the slot runtimes (a converted artifact is its own row), a runtime it needs publishes no package for the slot platform under the pyproject pins, or the row identity names no acquirable artifact (recorded executions stand); each carries its reason in the note.
