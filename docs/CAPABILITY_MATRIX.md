# Capability and qualification matrix

Updated **2026-11-14** for source `0.5.28.dev0+accelerators1` (commit `1ada906`). Three parts: the implemented surface per family, the hardware scope, and one bounded summary per evidence id (E-001 to E-109). The [checklist](PROGRESS.md) has **32 bounded closures and 63 open items**; the [execution matrix](EXECUTION_MATRIX.md) (built 2026-09-28, after E-108) has 242 verifier-upheld pass cells of 1,232 (242 pass, 9 fail, 9 partial, 274 untried, 698 not applicable). E-109 (2026-11-13) qualifies a native llama.cpp catalog through Titanos's routes, not a matrix-kit run, and changes no execution-matrix cell. The cloud broker and the Studio redesign of 2026-10-01 to 2026-10-03 have no evidence row here: their proofs are mock cells of the [broker matrix](BROKER_MATRIX.md) and Node UI checks, not model-on-hardware execution, and they change no closure. Package and source identities named inside evidence rows (archives, executables and versions such as `0.5.27.dev0+assetjobs1`) are the historical bindings of those rows, not the current source version. A later source change never alters a delivered package's qualification.

**Implemented** means an adapter/schema/path exists in source. **Profile available** means a compatible catalog entry exists, not that it installed or executed successfully. **Bounded native pass** means the named model/package/platform/workload passed the recorded gate. **Source-tested** means deterministic source tests, not hardware proof. **Partial/failed** preserves useful observations without declaring the whole attempt successful. **Unverified/planned** is not execution evidence. Historical rows do not qualify the current source on every platform. "Vega" names the project's reference narration voice used as a speech fixture (request voice id `vega`); it is not a model or a product.

**Acceptance layers (separated on 2026-09-21):** ENGINE_CONTRACT covers coherent intended-modality execution, encoding/storage, declared controls, protocol, routing and lifecycle. MODEL_QUALITY retains factual/semantic/cosmetic performance. HUMAN_PRESENTATION covers demo media and human review. Wrong facts or cosmetic backgrounds alone do not fail the engine; malformed outputs, broken requested schema enforcement, controls and lifecycle remain engine defects. All 95 rows identify their layer in the [ledger](progress.json); original outputs remain retained.

**Hosts and records.** Evidence rows name machines by role (for example "this workstation", "the Turing laptop (RTX 2070 Max-Q, Windows x64)", `snapdragon-x-laptop-win-arm64`) and receipts by run label. Machine names, addresses and record paths are operator circumstances, not part of any claim. Row links target dated evidence pages that stay in the maintainers' private repository; the public source copies exclude them ([public export hygiene](DISTRIBUTION.md#public-export-hygiene)), so those links do not resolve there by design.
